## Пункт 24. Проверка результата

Очень важно убедиться, что наш "космический корабль" готов к полету! Открой файл `index.html` в браузере и проверь что:
- все элементы отображаются корректно;
- картинки загрузились;
- игра работает (плитки перемешиваются, собираются, появляется модальное окно).

> Но перед этим не забудь сохранить все изменения в файлах!

> **Как открыть файл в браузере:**
> * Найди файл `index.html` в папке проекта (это можно сделать, например, через Проводник);  
> * Дважды кликни по нему — он откроется в браузере по умолчанию;  
> **или:**
> * Кликни правой кнопкой мыши по файлу → «Открыть с помощью» → выбери браузер (Chrome, Edge, Safari и т.д.);

Если что-то пошло не так, не расстраивайся! Просто вернись к предыдущим шагам, внимательно перечитай инструкции и найди ошибку. Исправь ее, и твой сайт обязательно "взлетит"!

## Пункт 25. Публикация сайта на GitVerse Pages

Твой сайт готов и прекрасно работает на твоем компьютере. Но чтобы его увидели другие, его нужно "выставить в космос" – опубликовать в интернете!  

**GitVerse Pages** – это отличный инструмент, который позволяет сделать это бесплатно и очень просто.

### Шаг 1: Сохранение изменений

Сейчас все файлы находятся только у тебя. Это не очень удобно, особенно если ты работаешь в команде. На помощь приходит `Git` – система контроля версий. Она позволяет отслеживать все изменения в проекте и синхронизировать их с удаленным хранилищем. У тебя уже есть готовый репозиторий в GitVerse – отличная отправная точка!

GitVerse также предоставляет хостинг – место, где твой сайт будет "жить" в интернете.

Зайди на [GitVerse](http://gitverse.ru), авторизуйся, если уже успел выйти, и выбери репозиторий твоего проекта. Ты увидишь, что там пока только та версия, с которой ты начал. `Git` не отправляет изменения автоматически – это было бы слишком расточительно.

### Шаг 2: Отправка изменений

Теперь мы отправим все наши изменения в удаленный репозиторий. Это делается с помощью нескольких простых команд в консоли (текст комментария к коммиту поменяй на свой, например "Постройка космолета"):
```bash
git add .
```
```bash
git commit -m "Текст комментария к коммиту"
```
```bash
git push
```
После выполнения этих команд обнови свой репозиторий на GitVerse – и ты увидишь все свои изменения! Поздравляем, ты сохранил прогресс!

### Шаг 3: Проверка наличия главного файла

Чтобы GitVerse Pages знал, что загружать, убедись, что в корне твоего репозитория (самая главная, первая папка `cosmo_site`) лежит файл `index.html`. Это главная страница твоего сайта.

### Шаг 4: Включение GitVerse Pages
Перейди в "Настройки" (Settings) твоего репозитория. В меню слева выбери "Страницы" (Pages).
- включи функциональность Pages с помощью переключателя (тумблера);
- в поле "Источник" (Source) выбери "Ветка" (Branch);
- выбери ветку, из которой будет выполняться сборка — в нашем случае это develop;
- нажми "Сохранить" (Save).

### Шаг 5: Ожидание публикации и проверка статуса

После сохранения система начнет сборку и публикацию твоего сайта. Это займет несколько минут. Статус публикации затем изменится на "Опубликован", и появится заветная ссылка на твой сайт!

### Шаг 6: Просмотр опубликованного сайта

После успешной публикации твой сайт будет доступен по адресу: `https://<твой_логин>.gitverse.site/<название_репозитория>/`
Например, если твой логин `user123`, а репозиторий называется `cosmo_site`, сайт откроется по адресу: `https://user123.gitverse.site/cosmo_site/`

Сохрани эту ссылку! Создай файл `url.txt` в корне репозитория, помести туда адрес твоего сайта, сохрани и снова проделай действия из Шага 2, только с другим комментарием к коммиту.

### Шаг 7: Если сборка завершилась с ошибкой

Не переживай, если сборка завершилась с ошибкой. Проверь следующее:
- репозиторий должен быть публичным ("Public");
- в корне репозитория обязательно должен быть файл `index.html`;
- все пути к файлам внутри проекта должны быть относительными (начинаться с *`css/`*, *`js/`*, *`shared/`*, а не с *`D:\`* или *`C:\`*);
- названия папок и файлов должны содержать только латинские буквы в нижнем регистре, без пробелов и спецсимволов.

Если ошибка сохраняется, нажми на ссылку с логом сборки на странице "Страницы" — там будет подробное описание проблемы.
